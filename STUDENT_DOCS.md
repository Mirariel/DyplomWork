## ВСТУП

### Мета роботи

Метою дипломної роботи є проєктування та реалізація мультибіржового портфельного трекера криптовалютних активів **TradeTracker** на мові програмування Go, що забезпечує автоматизований збір торгових даних з декількох криптовалютних бірж у реальному часі, управління позиціями та підтримку торгових ботів.

### Завдання роботи

Для досягнення поставленої мети необхідно виконати такі завдання:

1. Дослідити предметну область криптовалютної торгівлі та існуючі рішення (Bitsgap, 3Commas, CoinTracking).
2. Спроєктувати архітектуру системи на базі мікросервісного підходу з HTTP API та WebSocket.
3. Реалізувати уніфіковані адаптери для підключення до бірж Binance, OKX та Bybit через їхні REST API.
4. Розробити сервіс синхронізації балансів, відкритих позицій та торгової історії.
5. Реалізувати WebSocket-сервер для передачі даних клієнту в режимі реального часу.
6. Забезпечити безпеку даних: шифрування API-ключів (AES-256-GCM) та авторизацію через JWT.
7. Покрити критичні компоненти автоматизованими тестами.

### Об'єкт дослідження

Об'єктом дослідження є процес агрегації та обробки торгових даних з різнорідних криптовалютних бірж у режимі реального часу в умовах high-concurrency навантаження.

### Предмет дослідження

Предметом дослідження є методи та інструменти побудови конкурентних серверних застосунків мовою Go для роботи з фінансовими API, включаючи горутини, канали, WebSocket та механізми кешування.

### Актуальність

Криптовалютний ринок 2024–2025 років характеризується стрімким зростанням кількості торгових платформ і активних трейдерів. За даними CoinGecko, щоденний обсяг торгів на централізованих біржах перевищує $50 млрд, а кількість активних користувачів таких платформ, як Binance та Bybit, сягає десятків мільйонів.

Більшість трейдерів використовують одночасно 2–5 бірж, що породжує проблему фрагментованості даних: балансів, відкритих позицій та PnL. Існуючі рішення (Bitsgap, 3Commas) є або дорогими (від \$29/міс), або мають обмежений набір бірж.

Водночас традиційні серверні технології (PHP, Python) погано масштабуються при одночасній підтримці сотень WebSocket-з'єднань та паралельних API-запитів до кількох бірж, де кожна має власне rate-limiting та формат підпису запитів.

Мова Go, зі своєю моделлю конкурентності на основі горутин та каналів, є природним вибором для таких латентно-чутливих (latency-sensitive) систем. Актуальність роботи підтверджується відсутністю повноцінних відкритих реалізацій подібного класу систем українською академічною спільнотою.

### Практичне значення

Практичне значення роботи полягає в:

- **Готовому продукті:** TradeTracker може використовуватися безпосередньо як персональний трекер криптопортфеля без платних підписок.
- **Переносимості рішення:** уніфікований інтерфейс `Exchange` дозволяє додавати нові біржі без змін в основній логіці сервісу.
- **Освітній цінності:** проєкт демонструє практичне застосування конкурентного програмування, REST-інтеграцій з HMAC-підписами та безпечного зберігання секретів.
- **Масштабованості:** архітектура передбачає подальший розвиток: торгові боти, аналітика PnL, AI-радник, розбиття на мікросервіси та комерційну монетизацію через підписки.

## РОЗДІЛ 1. ОПИС ТЕХНОЛОГІЧНОГО СТЕКУ

### 1.1 Мова програмування та середовище виконання

Серверна частина системи реалізована мовою **Go (Golang) 1.21+**. Go обрано через нативну підтримку конкурентності (горутини, канали), компільований бінарник без зовнішніх залежностей та продуктивність, порівняну з C++ у мережевих задачах. Пакет `slog` (stdlib 1.21) використовується для структурованого логування у форматі JSON (prod) або human-readable (dev).

### 1.2 HTTP-фреймворк

**Fiber v2** (`gofiber/fiber/v2 v2.52.12`) — HTTP-фреймворк на базі `fasthttp`, що демонструє пропускну здатність до 8× вище порівняно з `net/http` у бенчмарках. Маршрутизація, middleware (CORS, rate limiting, JWT), обробка JSON — все реалізовано через Fiber. Rate limiting на `/api/auth/*` обмежує 10 запитів/хв на IP для захисту від brute-force.

### 1.3 База даних

**MySQL** (WAMP, порт 3306), схема `tradetracker_go`. Доступ через **sqlx** (`jmoiron/sqlx`) — тонка обгортка над `database/sql` з підтримкою іменованих параметрів і `StructScan`. Драйвер: `go-sql-driver/mysql`. Фінансові значення зберігаються як `DECIMAL(20,8)` для уникнення похибок float. Схема керується міграціями через **golang-migrate/migrate/v4**.

### 1.4 Автентифікація та безпека

- **JWT** (`golang-jwt/jwt/v5`) — токени передаються через `Authorization: Bearer` або HttpOnly cookie.
- **AES-256-GCM** (stdlib `crypto/aes`) — API-ключі бірж шифруються перед записом у БД; ключ шифрування береться з `APP_KEY` в `.env`.

### 1.5 WebSocket

**gofiber/websocket/v2** забезпечує Upgrade-механізм. Архітектура Hub/Client: кожен клієнт — дві горутини (ReadPump + WritePump). Сервер бродкастить дані кожні 2 секунди: поточні ціни з in-memory кешу (TTL 30s, `sync.RWMutex`) та відкриті позиції користувача.

### 1.6 Адаптери бірж

Уніфікований інтерфейс `Exchange` з методами `GetBalance`, `GetPositions`, `GetClosedTrades`. Реалізовано три адаптери:

| Адаптер | API | Особливості |
|---|---|---|
| `binance.go` | V3 Spot + FAPI Futures | HMAC-SHA256, timestamp |
| `okx.go` | V5 | Trading + Funding + Earn рахунки |
| `bybit.go` | V5 UTA | 7-денні вікна, cursor pagination |

Спільна HTTP-інфраструктура (`client.go`): автоматичний retry при HTTP 429 (rate limit).

### 1.7 Конфігурація

**godotenv** (`joho/godotenv v1.5.1`) завантажує `.env` у змінні середовища при старті. `Config` struct у `internal/config/config.go` є єдиною точкою доступу до налаштувань.

## ВИСНОВКИ

У ході виконання практичної роботи було описано концепцію та технологічний стек дипломного проєкту **TradeTracker** — мультибіржового портфельного трекера криптовалютних активів.

Обґрунтовано вибір мови Go як основного інструменту реалізації, що забезпечує необхідну продуктивність та конкурентність для latency-sensitive фінансового домену. Описана архітектура демонструє застосування сучасних підходів: уніфіковані Exchange-адаптери, шифрування секретів, JWT-авторизація, WebSocket real-time updates та міграційне управління схемою БД.

Практична цінність системи підтверджується її готовністю до використання як персонального трекера без сторонніх підписок, а також архітектурною відкритістю до розширення — додавання нових бірж, торгових ботів та AI-аналітики на базі Claude API.

Результати роботи можуть бути застосовані як основа для комерційного SaaS-продукту або як академічна демонстрація сучасних практик розробки конкурентних серверних систем на Go.
